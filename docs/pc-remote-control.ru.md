# Управление роботом с ПК по Wi‑Fi (не прошивка Romeo)

На Raspberry Pi программа `send --listen` делает две вещи:

1. **Видео** — один TCP‑порт (MJPEG), как раньше.
2. **Команды Romeo** — отдельный TCP‑порт; всё, что приходит с ПК по этому порту, Pi пересылает на USB `/dev/ttyACM*` как текстовые строки (плюс опциональный JSON → те же команды).

Ниже — как встроить это в приложение на Windows/Linux/macOS.

---

## 1. Узнать адрес и порты Pi

### Вариант A: UDP discovery (как у вашего приёмника видео)

- Шлёте на broadcast UDP запрос с тем же портом и форматом, что уже использует ваш клиент для поиска Pi (поле `cmd: discover` и т.д.).
- В ответе от Pi в JSON есть минимум:
  - **`tcp`** — порт **видеострима**;
  - **`control`** — порт **управления** (если на Pi не отключали `--romeo-control-port 0`).

Сохраните `ip` отправителя ответа, подключайтесь к `ip:tcp` для картинки и к `ip:control` для команд.

### Вариант B: без discovery

- Задаёте IP Pi вручную (например `192.168.1.50`).
- Порт видео — тот, что задан на Pi (`send --listen --port 5000` → обычно **5000**).
- Порт управления по умолчанию **5001** (`--romeo-control-port`), если не меняли.

---

## 2. Отдельное TCP‑соединение только под команды

Откройте **один долгоживущий** TCP‑клиент на `IP:control` (например `192.168.1.50:5001`).

- Кодировка: **UTF‑8**.
- Формат: **одна логическая команда = одна строка, в конце символ перевода строки `\n`** (как «Serial Monitor» с включённым newline).
- Ответ от Pi: **одна строка JSON на каждую отправленную строку** (удобно читать построчно).

Пример ответа:

```json
{"ok": true, "reply": "OK\r\n"}
```

При ошибке:

```json
{"ok": false, "error": "..."}
```

Поле **`reply`** — это сырой ответ прошивки Romeo (может быть пустым).

---

## 3. Что слать на Pi

### 3.1. Текстом — как в Serial к Romeo

Любая строка из справки прошивки, например:

```text
MF
MB
MS
TL
TR
TANK 200 -200
PANL
TILTU
PL
PR
TU
TD
TS
HOME
```

Каждая строка заканчивается `\n`.

### 3.2. JSON — удобно из кнопок и стрелок

Одна строка JSON + `\n`:

| Действие | Пример строки (отправить как одну линию + `\n`) |
|----------|--------------------------------------------------|
| Вперёд / назад / стоп | `{"action":"drive","dir":"forward"}` / `"back"` / `"stop"` |
| Разворот на месте | `{"action":"drive","dir":"left"}` → **TL**, `"right"` → **TR** |
| Две гусеницы | `{"action":"tank","left":200,"right":-200}` или ключи `l` / `r` |
| Башня (шаг) | `{"action":"turret","dir":"left","step":1}` — **мелкий шаг (1–2°) + частые повторы** = плавно |
| Башня (как в прошивке) | `{"action":"turret","dir":"up"}` — без `step` (шаг по умолчанию в прошивке, часто крупный) |
| Угол PAN/TILT | `{"action":"pan","deg":45}` / `{"action":"tilt","deg":20}` / `{"action":"aim","pan":45,"tilt":20}` |
| **Плавная башня по направлению** | `{"action":"turret_smooth","dir":"left","v":20}` → **PL 20**; `dir`: `left`/`right`/`up`/`down` → **PL**/**PR**/**TU**/**TD**; без `v` — скорость по умолчанию в прошивке |
| **Плавный поворот/наклон со знаком (град/с)** | `{"action":"pan_vel","v":12}` → **PANV**, `{"action":"tilt_vel","v":-8}` → **TILTV** |
| Обе оси скоростью | `{"action":"turret_vel","pan":10,"tilt":3}` → **TURRETV**; можно только `pan` или только `tilt` |
| Стоп плавного хода | `{"action":"turret_stop"}` → **TS** (синоним **TSTOP** в прошивке) |
| Домой | `{"action":"home"}` |
| Произвольная команда | `{"romeo":"FIRE/IR"}` |

На Pi можно задать **`--romeo-turret-step 2`**: тогда JSON `turret` **без** поля `step` превратится в `PANL 2` / `TILTU 2` и т.д. (мельче, чем встроенный крупный шаг прошивки).

Если в прошивке есть **PL/PR/TU/TD** и **TS**, для стрелок удобнее **`turret_smooth`** (при **keyup** — **`turret_stop`** → **TS**). Альтернатива: **PANV** / **TILTV** / **TURRETV** и снова **`turret_stop`**.

### 3.3. Почему башня «дёргается» и как сделать плавно

Прошивка для `PANL` / `TILTU` без аргумента использует **свой** шаг (часто большой) — при каждом срабатывании кнопки на ПК серва перескакивает заметно.

**Сделайте на ПК один из подходов:**

1. **Команды PL/PR/TU/TD:** при удержании — `{"action":"turret_smooth","dir":"left"}` (опционально `"v":20`), при отпускании — **`turret_stop`** (**TS**).
2. **Или PANV/TILTV** с нужным знаком **v**, при отпускании — **`turret_stop`**.
3. **Мелкий шаг + чаще:** раз в **30–50 ms**  
   `{"action":"turret","dir":"left","step":1}` (или `step:2`).
4. **Параметр на Pi:** `--romeo-turret-step 2` для пошагового режима без явного `step` в JSON.

Не полагайтесь только на autorepeat клавиатуры: лучше **turret_smooth** на keydown/keyup или таймер для пошагового режима.

Точное соответствие строк прошивке — в `rpi_tools/romeo_control_server.py`.

### 3.4. Рывки только у серв, моторы нормальные

Тогда **PWM-рампа для гусениц не нужна** — имеет смысл только башня.

1. **На ПК:** предпочтительно **`turret_smooth`** + **`turret_stop`** (→ **PL**…**TS**), либо **PANV/TILTV** + **`turret_stop`**. Иначе — малый **`step`** и таймер (§3.3).
2. **В прошивке** сглаживание внутри PL/PANV — тогда не нужен спам `PANL`.

## 4. Как привязать клавиатуру в приложении на ПК

Логика только на стороне клиента:

1. Пока стрелка зажата — **`turret_smooth`** с **`dir`** (и опционально **`v`**), либо **`pan_vel`/`tilt_vel`**, либо **`turret`** с малым **`step`** по таймеру. При **keyup** башни — **`turret_stop`** (**TS**).
2. При **keyup** моторов — **`MS`** или `{"action":"drive","dir":"stop"}`.
3. Текстом: **`PL`**, **`TD 15`**, **`TS`**, **`TSTOP`** — тоже можно (см. §3.1).

Пример соответствия (можно поменять под себя):

- Вперёд / назад — `drive` forward / back.
- Влево / вправо на месте — `drive` left / right (→ TL/TR).
- Стрелки — **`turret_smooth`** + **`turret_stop`**, либо PANV/TILTV, либо **`turret`** с `"step":1` и таймер / `--romeo-turret-step` на Pi.

## 5. Минимальный пример (Python), только управление

```python
import socket
import json

HOST = "192.168.1.50"  # IP Raspberry Pi
CONTROL_PORT = 5001

def send_line(sock: socket.socket, line: str) -> dict:
    sock.sendall((line.rstrip("\n") + "\n").encode("utf-8"))
    buf = b""
    while b"\n" not in buf:
        chunk = sock.recv(4096)
        if not chunk:
            raise ConnectionError("соединение закрыто")
        buf += chunk
    first, _, rest = buf.partition(b"\n")
    return json.loads(first.decode("utf-8"))

with socket.create_connection((HOST, CONTROL_PORT), timeout=5) as s:
    r = send_line(s, '{"action":"drive","dir":"forward"}')
    print(r)
    r = send_line(s, "MS")
    print(r)
```

В реальном UI соединение **`with`** держите открытым всё время окна управления, а не на каждое нажатие.

## 6. Частые проблемы

- **Нет поля `control` в discovery** — на Pi запуск без `--romeo-control-port 0` и с `--listen`; либо задайте порт вручную (**5001** по умолчанию).
- **Таймауты** — не блокируйте UI поток; отправку лучше ставить в очередь или отдельный поток.
- **Один USB Romeo** — Pi сериализует команды; два клиента одновременно могут мешать друг другу — проще один TCP‑клиент управления с ПК.

Этого достаточно, чтобы реализовать вторую половину на любом стеке (Electron, Qt, Unity, браузер через нативный шлюз и т.д.): главное — TCP, строки с `\n` и разбор JSON‑ответов построчно.
