# Качество картинки стрима на Raspberry Pi («мыло», артефакты)

Размытие и «мазня» при движении почти всегда лечатся **на передатчике** (камера + сжатие + нагрузка на Wi‑Fi). Ниже — что крутить в `stream_camera.py send` / `rpi_tools/cli.py`.

## Главное

| Параметр | Смысл |
|----------|--------|
| **`--jpeg-quality`** | По умолчанию в проекте **88**. Выше (90–92) — меньше блочных артефактов при движении, **больше** трафика. Ниже — наоборот. |
| **`--width` / `--height`** | Чуть **меньше** разрешение часто даёт и стабильнее FPS, и меньше ощущения «мыльной» картинки при том же канале Wi‑Fi (меньше дропов и повторного сжатия «на глаз»). |
| **`--fps`** | Задаётся запрос к камере; если железо не тянет, реальный FPS будет ниже — перегрузка даёт дропы кадров и рваное видео. |
| **`--timestamp`** | Включать только если нужно; текст по кадру добавляет детали и **мелкий шум** в JPEG вокруг букв. |

Примеры:

```bash
python stream_camera.py send --listen --jpeg-quality 90 --width 640 --height 480
python stream_camera.py send --listen --jpeg-quality 92 --width 512 --height 384
```

## Свет и экспозиция

При плохом освещении камера удлиняет выдержку → смаз по движению в **исходном** кадре; JPEG тут ни при чём. Имеет смысл больше света, фиксированная выдержка/ISO в настройках камеры (если позже добавите тюнинг `picamera2` в коде).

## Итог

Сначала поднимите **`--jpeg-quality`** и при узком канале попробуйте **чуть снизить разрешение**; отключите **`--timestamp`**, если не нужен. На приёмнике (ПК) масштаб окна только растягивает пиксели — «лечит» не качество источника, а удобство просмотра.
