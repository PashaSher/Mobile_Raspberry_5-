# Качество картинки стрима на Raspberry Pi («мыло», артефакты)

Размытие и «мазня» при движении почти всегда лечатся **на передатчике** (камера + сжатие + нагрузка на Wi‑Fi). Ниже — что крутить в `stream_camera.py send` / `rpi_tools/cli.py`.

## Пресеты `--stream-preset` (профессиональная передача)

| Пресет | Назначение |
|--------|------------|
| **broadcast** (по умолчанию) | 720p, 30 FPS, JPEG ~92, цвет **4:2:2**, 8 потоков кодирования — хороший баланс качества и битрейта для Wi‑Fi. |
| **cinema** | 720p, 24 FPS, JPEG ~95, **4:4:4**, точнее DCT (`--no-jpeg-fast-dct`) — максимум деталей при более спокойном темпе. |
| **mobile** | 960×540, 30 FPS, JPEG ~88, **4:2:0** — проще держать стабильный поток на слабом канале. |
| **custom** | Только явные `--width`, `--fps`, `--jpeg-quality`, … |

Основной контур на Raspberry Pi: **picamera2 `JpegEncoder`** (несколько потоков `simplejpeg`, как в официальном `mjpeg_server.py`) → ваш протокол TCP «4 байта + JPEG». Запасной путь: `capture_array` + JPEG (например при `--timestamp` или `--legacy-picamera-jpeg-loop`).

## Почему «рвано» в движении

1. **Неравные интервалы между кадрами** — если Pi кодировал и слал «как успеет», паузы между кадрами скачут; при движении это выглядит дергано. В коде для **picamera2** задаётся **равномерный темп** по `--fps` (лимит длительности кадра в libcamera + лёгкая пауза между итерациями).

2. **Низкий или нестабильный FPS по Wi‑Fi** — при узком канале кадры теряются или буферизуются на приёмнике. Попробуйте **`--fps 20`** или **`--fps 15`** и чуть меньше разрешение.

3. **Смаз в кадре** — при слабом свете камера удлиняет выдержку → размытие **до** JPEG; это не лечится повышением FPS на ПК.

## Главное

| Параметр | Смысл |
|----------|--------|
| **`--stream-preset`** | По умолчанию **broadcast** (баланс качества и FPS). Для максимума деталей: **`cinema`**; для стабильного потока: **`mobile`**. |
| **`--jpeg-quality`** | С пресетом **broadcast** обычно **~92**; ниже — меньше трафика при узком Wi‑Fi. |
| **`--jpeg-chroma`** | **422** (по умолчанию с broadcast) — меньше цветовых артефактов чем 420 при приемлемом битрейте; **444** максимум цвета, тяжелее по сети. |
| **`--width` / `--height`** | Пресеты задают разрешение; при **`custom`** по умолчанию **1280×720**; при рывках уменьшайте (например 960×540). |
| **`--fps`** | Пресеты задают целевой FPS; если Pi не успевает, задайте **20** или **15**. |
| **`--legacy-picamera-jpeg-loop`** | Принудительно старый цикл `capture_array` + JPEG (медленнее; только для отладки). |
| **`--jpeg-tcp-queue N`** | По умолчанию **2**: отправка JPEG в отдельном потоке — если ПК читает TCP редко (например UI занят клавишами), кодер на Pi не «застывает». **0** — без очереди (все кадры доходят, но возможны блокировки при медленном приёмнике). Подробнее: `docs/pc-remote-control.ru.md` §6. |
| **`--timestamp`** | Включать только если нужно; текст по кадру добавляет детали и **мелкий шум** в JPEG вокруг букв. |

Примеры:

```bash
# Рекомендуемый режим (JpegEncoder, 422, многопоточный JPEG):
python stream_camera.py send --listen

# Максимум качества картинки (24 FPS, 444):
python stream_camera.py send --listen --stream-preset cinema

# Слабый Wi‑Fi — меньше битрейт и разрешение:
python stream_camera.py send --listen --stream-preset mobile

# Ручные параметры поверх defaults:
python stream_camera.py send --listen --stream-preset custom --jpeg-quality 88 --width 960 --height 540 --fps 20
```

## Свет и экспозиция

При плохом освещении камера удлиняет выдержку → смаз по движению в **исходном** кадре; JPEG тут ни при чём. Имеет смысл больше света, фиксированная выдержка/ISO в настройках камеры (если позже добавите тюнинг `picamera2` в коде).

## Итог

Начните с **`--stream-preset broadcast`** (по умолчанию): многопоточный **JpegEncoder**, **4:2:2**, темп по FPS. При узком канале — **`mobile`** или ручное снижение `--jpeg-quality` и разрешения; для максимальной детализации статичных сцен — **`cinema`**. Отключите **`--timestamp`**, если подпись не нужна. На приёмнике масштаб окна только растягивает пиксели — «лечит» не качество источника, а удобство просмотра.
